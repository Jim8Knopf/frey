# dockge

A web UI that lists the Docker Compose stacks on the Pi, so you can see what is
running without remembering which of twenty-odd container names belongs to
which stack.

```bash
ansible-playbook -i inventory/hosts.yml playbooks/site.yml \
  --tags dockge --vault-password-file .vault_pass
```

`https://dockge.hub.frey` — behind single sign-on, `frey_admins` only.

## Read this before changing anything in it

Dockge can edit compose files. The Frey stacks are generated by Ansible, and
every one of them opens with:

> Do not edit on the Pi; changes are overwritten on the next deploy.

That is still true with Dockge installed. Anything you change through the UI
lasts exactly until the next `ansible-playbook`, which rewrites the file from
its template and recreates the containers. Stopping a service has the same
fate: the next deploy starts it again, because the roles declare compose
`state: present`.

So treat it as a window, not a control panel:

| Fine | Not fine |
| --- | --- |
| Seeing what is running, and in which stack | Editing a `frey_*` stack's compose file |
| Reading logs | Changing an image tag here |
| Restarting a container to clear a transient fault | Stopping a service you want to stay stopped |

`dockge.stacks_writable: false` (the default) enforces that by mounting
`/opt/frey/stacks` read-only, so the UI shows the stacks and refuses to save
over them. Set it `true` if you would rather have the rope — the role prints a
warning when you do.

To make a change that lasts, edit `roles/<module>/templates/` and deploy.

## Why it is behind forward auth, and why that is not negotiable

Dockge holds the Docker socket. That is root on the host under another name:
anything that can reach it can start a privileged container with the host
filesystem mounted and own the Pi.

Dockge does have its own login, but it is a **first-run setup wizard** — an
unprotected instance lets whoever reaches it first create the admin account. So
it sits behind Authelia (`forward_auth` in `inventory/group_vars/all/identity.yml`,
`frey_admins` only), and Authelia answers before Dockge ever sees the request.

## Relationship to the monitoring module

None, deliberately. Dockge is for *looking* at the stack; `roles/monitoring/`
is for *knowing* it is healthy and being told when it is not. Dockge shows you
a container is restarting if you happen to be looking; the monitoring module
sends `FreyContainerRestartLoop` to your phone whether you are or not.

Nothing depends on Dockge, and removing it from `frey.modules.enabled` costs
nothing but the convenience.

## Variables

- `dockge_version` — in `inventory/group_vars/all/images.yml`, pinned
- `dockge.stacks_writable` — read-only by default; see above
- `dockge.host` — the hostname, `dockge` by default

Adding it to `identity_services` is what puts `dockge.hub.frey` in the
certificate, gives it an Authelia access-control rule, and starts the
monitoring module probing it — all from the one entry.
